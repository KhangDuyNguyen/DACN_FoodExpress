# Tuần 4 — Merchant Dashboard: quản lý chi nhánh và menu

Backend (Spring Boot) và frontend (React/TypeScript) cho phép chủ quán chọn/tạo chi nhánh, chỉnh thông tin quán, cập nhật giờ mở cửa, và CRUD đầy đủ danh mục → món → nhóm tùy chọn → tùy chọn. Tất cả endpoint đều đặt sau guard `MERCHANT` role trong SecurityConfig. Tổng thể thiết kế rõ ràng, ownership check nhất quán, API-frontend khớp tốt.

**Watch for:**
1. `MerchantLayout.tsx` thiếu 3 import icon từ `@ant-design/icons` — app sẽ crash khi render sidebar **(confirmed, blocking)**
2. Java record `boolean isAvailable` / `boolean isRequired` serialize thành `"available"` và `"required"` trong JSON, không phải `"isAvailable"` / `"isRequired"` — gây request frontend gửi sai field, backend nhận `false` mặc định **(confirmed, blocking)**
3. `RestaurantSettings.tsx` gọi `fetchRestaurantById` (public endpoint `/api/restaurants/{id}`) để load thông tin quán cho merchant, nhưng endpoint này chỉ trả quán `status=ACTIVE` — quán `PENDING/HIDDEN/SUSPENDED` sẽ không tải được **(confirmed, behavioral bug)**

**Verdict**: NEEDS_CHANGES

---

## High-level view

`BranchProvider` bọc toàn bộ merchant route tree trong `App.tsx`, lưu chi nhánh đang chọn vào localStorage để giữ qua refresh. `BranchSelector` và `MenuManagement`/`RestaurantSettings` đọc context này; nếu context rỗng thì redirect về `/merchant/branch`. Luồng điều hướng logic và đúng.

Toàn bộ thao tác với menu đặt dưới `MerchantMenuController` (không có `@RequestMapping` class-level), endpoint khai báo đầy đủ path trực tiếp trên từng method. `MerchantMenuService` thực thi ownership check bằng `requireOwner` trước mọi thao tác, sau đó kiểm tra thêm quan hệ cha–con (category thuộc quán, item thuộc category, group thuộc item). Chuỗi kiểm tra này đúng và nhất quán.

`MerchantLayout.tsx` sử dụng ba icon `BranchesOutlined`, `UnorderedListOutlined`, `SettingOutlined` nhưng không import chúng — đây là lỗi compile-time của React/JSX sẽ khiến sidebar không render được.

Java record với `boolean isAvailable` sinh ra accessor `isAvailable()`, Jackson mặc định hiểu đây là JavaBean getter và serialize thành key `"available"` (bỏ prefix `is`). Frontend trong `merchant.ts` gửi và đọc `isAvailable` / `isRequired`; backend nhận JSON không có đúng key, deserialize về `false` mặc định. Mọi thao tác tạo/sửa món và tùy chọn đều bị ảnh hưởng.

`RestaurantSettings.tsx` dùng `fetchRestaurantById(rid)` từ `restaurants.ts` để load thông tin quán. Hàm này gọi `/api/restaurants/{id}` — public endpoint, chỉ trả quán có `status = 'ACTIVE'`. Quán mới tạo (PENDING) hoặc bị ẩn sẽ trả 404, form cài đặt bị trắng hoàn toàn.

## Ba icon thiếu import làm crash sidebar

`MerchantLayout.tsx` khai báo menu với:

```tsx
icon: <BranchesOutlined />,
icon: <UnorderedListOutlined />,
icon: <SettingOutlined />,
```

Block import từ `@ant-design/icons` (dòng 16–30) chỉ có: `DashboardOutlined`, `ShoppingOutlined`, `TagOutlined`, `LineChartOutlined`, `FireOutlined`, `CustomerServiceOutlined`, `LogoutOutlined`, `MenuFoldOutlined`, `MenuUnfoldOutlined`, `ShopOutlined`, `UserOutlined`, `BellOutlined`. Ba icon kia không có. TypeScript compiler không bắt lỗi này vì `tsconfig` không strict-check JSX identifier resolution theo cách này, nhưng tại runtime React sẽ throw `ReferenceError: BranchesOutlined is not defined` khi render Sidebar. Ba icon này đều tồn tại trong gói đã cài (`node_modules/@ant-design/icons`), chỉ cần thêm vào import.

## `isAvailable` / `isRequired` serialize sai tên field trong JSON — confirmed

Jackson serializes Java record components dựa trên accessor method name, không phải field name. Với `boolean isAvailable`, accessor là `isAvailable()` — Jackson sẽ tạo JSON key `"available"` (bỏ prefix `is`). Tương tự `boolean isRequired` → `"required"`.

Các record bị ảnh hưởng và hậu quả cụ thể:

| Record | Field | JSON key thực tế | Frontend gửi | Kết quả |
|---|---|---|---|---|
| `AvailabilityRequest` | `isAvailable` | `available` | `{ isAvailable: true }` | Backend nhận `false` (default) |
| `MenuItemRequest` | `isAvailable` | `available` | `{ isAvailable: true }` | Món luôn tạo với `is_available=false` |
| `OptionGroupRequest` | `isRequired` | `required` | `{ isRequired: true }` | Nhóm tùy chọn luôn `required=false` |
| `OptionRequest` | `isAvailable` | `available` | `{ isAvailable: true }` | Tùy chọn luôn tạo với `is_available=false` |
| `OptionGroupDTO` (response) | `isRequired` | `required` | Frontend đọc `dto.isRequired` | luôn `undefined`/`false` |
| `OptionDTO` (response) | `isAvailable` | `available` | Frontend đọc `dto.isAvailable` | luôn `undefined`/`false` |

Sửa bằng cách thêm `@JsonProperty` trên từng boolean field, ví dụ:

```java
public record MenuItemRequest(
    ...
    @JsonProperty("isAvailable") boolean isAvailable,
    ...
) {}
```

Hoặc đổi tên component thành `available` và cập nhật tất cả TypeScript types và usages tương ứng.

## RestaurantSettings load quán qua endpoint sai

`RestaurantSettings.tsx` dùng `fetchRestaurantById(rid)` từ `api/restaurants.ts`, gọi `GET /api/restaurants/{id}`. Repository query đó có điều kiện `WHERE r.status = 'ACTIVE'`. Merchant sau khi tạo chi nhánh mới sẽ có `status = 'PENDING'`; click vào để edit thì form cài đặt không load được vì API trả 404 → `useQuery` rơi vào error/loading mãi.

Giải pháp ít xâm lấn nhất: sử dụng thông tin đã có trong `selectedBranch` từ context để populate form cơ bản (name, address đã có), và thêm một query riêng chỉ khi cần các trường bổ sung (hours, description...) qua một endpoint merchant-scoped.
